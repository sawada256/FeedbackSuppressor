# Feedback Suppressor V2.1 変更内容と同等性の検証

V2.1 は、V2（コミット `553ed6a`）の**検出アルゴリズムを一切変えずに**、不具合の修正と処理の軽量化だけを行った版です。
- 特徴量、しきい値、判定、ノッチの配置・深さ・解除のロジックは V2 と同じです。
- V2 や V3 とは別のプラグインとして登録されます。

| 項目 | 値 |
|---|---|
| 製品名 | Feedback Suppressor V2.1 |
| プラグインコード | `Fd21`（メーカーコード `LALb`） |
| バンドルID | `io.github.sawada256.feedbacksuppressorv21` |
| バージョン | 2.1.0 |
| 形式 | Universal（arm64 と x86_64）、ad-hoc 署名 |
| ブランチ | `v2.1` |
| ビルド先 | `build-v21` |

## 1. 修正内容

### 検出器：計算は軽くしたが、結果はビット単位で同じ
- **位相の一貫性（PLV）の計算**：V2 は過去の位相誤差を保存し、毎フレームその全履歴に対して cos と sin を計算し直していました（ビン数 × チャンネル数 × 8〜16 回の三角関数）。V2.1 は誤差を保存するときに cos と sin を一度だけ計算して保存し、あとは合計するだけにしました。足し合わせる値も順序も V2 と同じなので、結果は完全に一致します。
- **背景推定**：音楽対応モードの背景値は、V2 では全ビンを毎フレーム計算（ソートと pow）していました。V2.1 は、実際に参照されるピーク周辺のビンだけを、V2 と同じ式で必要なときに計算します。表示用の全ビン計算は、1回の呼び出しにつき1回だけ行います。
- **位相ボコーダの周波数**：ピークのビンでだけ、V2 と同じ式で必要なときに計算します。
- **Classic（Standard）モード**：結果に使われていなかった位相計算を省きました。モードを切り替えると履歴はクリアされるので、影響はありません。
- **無音時の処理**：V2 は無音のホップのたびに約0.5 MB の履歴クリアを繰り返していました。V2.1 では、すでにクリアされていればスキップします。

### リアルタイム処理の安全性
- **音声スレッドのロック**：V2 では音声スレッド上の `processAudio`、`updateTimers`、`updateParameters`（Q／Max Cut などの設定）が、UI や検出スレッドと同じ mutex を取っていました。V2.1 では音声スレッドはロックを使いません。ノッチの目標値はスロットごとの seqlock で受け渡します。
- **処理の移動**：リフトタイマーとパラメータ反映は解析スレッドに移しました。タイマーは処理したサンプル数で進むので、オフライン書き出しでも正しく動きます。
- **遅延の報告**：V2 は `setLatencySamples()` を音声スレッドから呼んでいました。V2.1 では解析スレッドが変化を検出し、メッセージスレッドから報告します（AsyncUpdater 経由）。
- **ホストのバイパス時**：V2.1 では `processBlockBypassed` でも Lookahead と同じ遅延をかけ、報告した遅延とずれないようにしました。

### クリック音と遷移の修正
- **ノッチを外す操作**：ノッチの削除、Clear Live、Clear All、フィルタ単位の Bypass、Bypass モード、リフト完了時の解放では、V2 はフィルタを即座に外していました。V2.1 では、V2 と同じ約10 ms の平滑化でゲインを 0 dB に戻してから止めます。
- **新しいノッチの立ち上がり**：V2 は解放したスロットを 1 kHz・0 dB に設定していたため、新しいノッチが 1 kHz から目的の周波数へスライドしながら深くなっていました。V2.1 では、ゲインが 0 dB 付近のフィルタは目的の周波数から直接立ち上がります。

### その他の修正
- **状態の復元**：V2 は新しいフィルタの ID を `getFilterSnapshots().back()` で推測していましたが、V2.1 では `addFilter()` が ID を返します。また、固定フィルタを含まないプリセットを読み込むと古い固定フィルタが消えるようにしました。パラメータツリーに `FixedFilters` 要素が混ざらないようにもしています。
- **NaN／Inf**：ビクアッドの状態が NaN／Inf になったら、自動でリセットして復帰します。リミッターは入力の NaN を 0 として扱います。
- **署名**：VST3／AU／Standalone のバンドルを、ビルド後に ad-hoc 署名し直します。V2 では `moduleinfo.json` の追加によって、署名の検証が失敗していました。

### V2 のまま変えていないもの
- 3 ms Lookahead の動作：ノッチの前で音声を遅らせるだけで、検出には役立ちません。切り替え時に1サンプルずつ遅延量を変える動作も V2 のままです。
- ビクアッドの演算精度：float のままです。ノッチの応答を V2 とビット単位で一致させるためです。
- 係数の更新方法：ゲインなどが変化している間は、1サンプルごとに係数を再計算します。変化が終わった後は、各チャンネルを短いループでまとめて処理するようにして、軽くしました。
- 検出の経路、しきい値、ノッチの Q、スロットの割り当てと奪い方：すべて V2 と同じです。

## 2. 同等性の検証（`tests/benchmark.cpp`、`FS_DUMP=<file>`）

V2（`553ed6a`）と V2.1 で同じベンチマークを実行し、すべての検出イベントを書き出して比較しました。各イベントのブロック番号、周波数、ピーク、突出量、推奨カット量、信頼度を記録しています。

対象の信号は次のとおりです。
- 成長するハウリング：18ケース × 3モード
- 誤検出用の5種類の音源：30 秒ずつ × 3モード
- 周波数精度用の純音：30音 × 3モード

| 比較項目 | 結果 |
|---|---|
| 検出イベント 10,828 行 | **完全一致**（`diff` で差分なし） |
| 検出時間、誤検出の回数（音源の種類別）、周波数誤差の集計 | **完全一致** |
| `dsp_test` の出力 | **完全一致** |
| `music_detection_test` の出力 | 1行を除いて完全一致。閉ループの抑圧量が V2 −56.5568 dB、V2.1 −56.5628 dB（差 0.006 dB） |

### 閉ループ（ノッチを信号経路に入れたフィードバック系）
閉ループでは、ノッチの出力が次の入力に戻るため、ノッチの立ち上がり方や外れ方の違いがその後の挙動に影響します。

- 「新しいノッチを目的の周波数から直接立ち上げる」修正だけを一時的に無効にしてビルドし、V2 と比べました。ノッチ状態のログは、最初のリフト解放（ブロック 1904、約10秒）まで完全に一致しました。その後の違いは、クリックをなくすための遷移の修正によるものです。
- 修正をすべて入れた状態で、12種類の音声シードを使い、最後の1秒の出力 RMS を比べました。

| モード | V2 の平均 | V2.1 の平均 |
|---|---:|---:|
| Advanced | −27.60 dB | −27.60 dB |
| Aggressive | −24.66 dB | −27.66 dB |
| Classic | −28.97 dB | −29.04 dB |

Aggressive で差が出たのは、V2 でシード7と12の2件がハウリングを残したまま終わった（−9.8 dB／−9.5 dB）ためです。V2.1 では、この2件も他のシードと同程度（−27.7 dB）まで抑えられています。それ以外のシードでは、差は 0.2 dB 以内です。
